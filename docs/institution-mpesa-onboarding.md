# Spark Stack Academy — Institution M-Pesa onboarding payments

## Payment flow

1. An institution submits its application with a Kenyan M-Pesa-enabled contact number.
2. An authorised administrator approves the application.
3. If the central onboarding fee is enabled, the approval function requests a Safaricom Daraja STK Push.
4. The payment is recorded in `institutionPayments` with a pending status and the Daraja CheckoutRequestID.
5. Safaricom calls the public `darajaInstitutionCallback` endpoint.
6. The callback is not trusted on its own. The backend queries Daraja STK Query and checks the expected amount, phone number and receipt number.
7. A verified payment is recorded as paid. If the pricing policy requires payment before activation, the institution and owner account are activated and the trial begins only after payment.
8. If the prompt fails, an authorised reviewer can use **Resend M-Pesa payment prompt** in Admin → Institutions.

## Pricing rules

- The onboarding fee is controlled in Admin → Institution Pricing.
- Daraja onboarding collection currently requires currency KES and a whole-number KES amount.
- `before_activation`: the institution remains pending payment; the 14-day trial begins after verified payment.
- `after_approval`: the institution workspace and trial begin after approval; the onboarding fee remains due and the STK prompt is sent after approval.
- The transaction fee remains a separately configurable setting. It is not included in this onboarding checkout.
- Instructor M-Pesa withdrawals are a separate payout workflow.
- Institution marketplace settlement continues directly to the institution's own merchant account.

## Firebase Secret Manager setup

Never place Daraja credentials in HTML, JavaScript, GitHub files, Firestore documents, or chat messages. Set them in the Firebase project connected to this repository.

Run these commands in the project root, and enter each value only in the secure CLI prompt:

```bash
firebase functions:secrets:set MPESA_CONSUMER_KEY
firebase functions:secrets:set MPESA_CONSUMER_SECRET
firebase functions:secrets:set MPESA_SHORTCODE
firebase functions:secrets:set MPESA_PASSKEY
firebase functions:secrets:set MPESA_ENVIRONMENT
firebase functions:secrets:set MPESA_TRANSACTION_TYPE
```

Set `MPESA_ENVIRONMENT` to `sandbox` while testing. Use `production` only after Safaricom has approved the production app and the merchant shortcode/passkey are ready. Set `MPESA_TRANSACTION_TYPE` to `CustomerPayBillOnline` for a PayBill shortcode or `CustomerBuyGoodsOnline` for an approved Till/Buy Goods shortcode.

The shortcode and passkey must belong to the same Daraja app/merchant configuration. The transaction type must match the Safaricom-approved merchant shortcode configuration.

## Deploy after sandbox configuration

After reviewing the branch and setting the secrets in the intended Firebase development project:

```bash
firebase deploy --only functions,firestore:rules
```

The deployment includes the approval, retry, callback and scheduled reconciliation functions, plus Firestore rules. Confirm that the callback URL generated by the function is reachable:

`https://us-central1-YOUR_FIREBASE_PROJECT_ID.cloudfunctions.net/darajaInstitutionCallback`

Register/allow this callback URL in the Safaricom Daraja app configuration where required.

## Sandbox test checklist

- Successful STK Push and correct callback CheckoutRequestID match.
- Successful STK Query result before marking a payment paid.
- Correct amount, payer phone and M-Pesa receipt validation.
- Failed/cancelled STK Push does not activate an institution.
- Duplicate callbacks do not double-activate or double-record payment.
- Delayed STK Query verification is reconciled by the scheduled function.
- Retry creates a new payment attempt without overwriting old payment history.
- `before_activation` starts the trial only after verified payment.
- `after_approval` allows the approved trial workspace while retaining a due onboarding fee until paid.
- Verify that payment records are not client-writable.
